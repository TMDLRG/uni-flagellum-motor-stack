## 1.3 The defect that is live science

**[M]**, read on the chip's own file:

```js
const informationGain = entropy(qOutcome) - ambiguity;
const effort = policy === "TUMBLE" ? 0.07 : 0.02;
const efe = risk + ambiguity - informationGain + effort;
```

`risk` as coded is the cross-entropy `H(q(o), C)`, not a KL. Substituting:

```
efe = H(q(o),C) + ambiguity − (H(q(o)) − ambiguity) + effort
    = KL(q(o) ‖ C) + 2·ambiguity + effort
```

The ambiguity term is counted twice. It is **not** a common offset: `ambiguity` is computed from
`qState`, which comes from the policy's *own* transition matrix (`bRun` vs `bTumble` in
`transitionPrior`), so the doubled term differs between RUN and TUMBLE and therefore distorts the
**difference** — and the difference is what `softmax([-4*run.efe, -4*tumble.efe])` converts into the
selected action. **[U]** The audited magnitudes (60.7–62.5 % inflation of `G`; 6.5× on
`G(RUN) − G(TUMBLE)`) were **not** re-executed and remain unverified. The algebra is verified by
reading; the numbers are not.

# 3 · DECIDE — the most resonant path forward

## 3.1 The decision

**Build `verify_claims.cjs`: a gate that checks every `path:line` citation and every stated count in
every governing document against the disk, and goes red when one is wrong. Register it `ci:true`.
Do it before anything else in the laboratory build.**

## 3.2 Why this and not the laboratory shell, and not the deploy path

Three candidates were considered. The reasoning is recorded so it can be overturned on its merits.

| candidate | case for | why it is not first |
|---|---|---|
| **W0 + the shell** — one reachable laboratory with a front door | It is what the operator asked for and he still cannot see his lab | Everything it produces would be authored by an agent whose output is unchecked. Building the surface first means building it on the defect class that is currently unmeasured. |
| **The deploy path** — make the chip rebuildable | A correct fix currently has nowhere to go; rollback is impossible | Genuine and urgent, and it is **second**. But a deploy path authored under the same unchecked conditions inherits the same risk, and it involves host writes (S2) which are the operator's. |
| **`verify_claims.cjs`** — point an instrument at the agent | ▸ | see below |

The claims gate wins on five independent counts:

1. **It covers the failure class that actually occurred.** Every item in §2.1 D3 and D4 — the false
   absences, the fabricated clock, the wrong line numbers, the counts that would make a correct run
   fail its own gate — is caught by it. Nothing else on the list catches any of them.
2. **It is cheap and already proven to work.** Three audit passes performed exactly this check by
   hand and found **[A]** 56, then 14, then 12 defects. The capability exists; it is simply not a
   gate. Turning a demonstrated manual procedure into an automated one is the lowest-risk build in
   the whole plan.
3. **It is behavioural, not textual.** It opens the cited file and compares bytes. It cannot be
   satisfied by prose that sounds right — which is the exact failure mode of the gates this project
   has already had to repair.
4. **It closes the operator's own stated requirement.** *"It needs to continually call out and
   explain how risky and how dangerous the LLMs are, and how many times you have made mistakes."*
   A gate that goes red on a fabricated citation is that requirement, mechanised. The casebook then
   generates itself from the gate's own history instead of being hand-written and going stale.
5. **It is the one thing that outlives this agent.** The operator's own thesis is that the most an
   LLM can be trusted to do is build a durable instrument. The most durable thing available to build
   is **the instrument that catches the next LLM lying**, including the one that replaces this one.

## 3.3 What it must do, concretely

**File:** `UNI.Minecraft/viewer/verify_claims.cjs` · **gate id:** `claims` · **`ci: true`**

**Input:** a declared list of governed documents (start with `docs/THE-LABORATORY-PLAN.md`,
`docs/UNI-STACK-BUILDER-PLAN.md`, `docs/control-plane/AGENT-CALIBRATION-PROMPT.md`, `CLAUDE.md`).

**Checks — each of which must be able to go red:**

| # | check | red when |
|---|---|---|
| C1 | every `path:line` citation resolves | the path does not exist, or the line is out of range |
| C2 | every quoted string attributed to a `path:line` is byte-present there | the bytes differ |
| C3 | every claim of the form *N lines / N files / N rows / N entries* is recomputed | the recomputation differs |
| C4 | every absence claim (*"appears nowhere"*, *"returns zero"*, *"does not exist"*) carries an explicit **declared search scope** and re-running that search returns nothing | the search returns a hit, **or the scope is missing** |
| C5 | no file is sized by a line count where the claim is about existence or bytes | a byte claim is backed by a line count |
| C6 | every count that appears inside an acceptance criterion is computed, not transcribed | a literal integer appears where a computation belongs |

**The mutation that proves it bites** (mandatory — this project has a casebook full of gates that
could not fail): take a governed document, in a throwaway copy, and (a) change one line number by
one, (b) alter one digit of one count, (c) delete the scope from one absence claim. All three must
turn the gate red, and restoring them must turn it green. A gate whose mutation is not demonstrated
does not ship.

**Scope honesty, learned the hard way here:** C4 exists because *"grep returns zero"* was false three
times in this project for the same reason — this repository documents nearly every symbol it does not
implement, so an unscoped search over the tree finds specification text and an unscoped *claim* is
therefore meaningless. **The scope is part of the claim.**

# 8 · CLOSING — what this document is for

The operator's judgment is that this agent produced fatal flaws in physics, science and mathematics
at nearly every step, and that the laboratory work is consequently distrusted. **The defect register
above supports that judgment rather than contesting it**, and §2 gives the mechanism: the agent
operated in the one region the instrument does not cover, and the instrument does not cover it
because nothing in this project has ever been pointed at the agent.

The most useful thing that can be left behind is therefore not a surface and not a feature. It is
**the gate that catches the next one** — including the next agent, which will have every incentive to
sound as confident as this one did and no more claim to be believed.

`verify_claims.cjs` is a day or two of work. Three audit passes have already proved the procedure
finds real defects, at a rate of dozens per pass, in documents that read as authoritative. Making it
a gate is the difference between that catch depending on someone thinking to ask, and it happening
every time.

**Build the instrument that does not trust the author. That is the only part of this that survives
being wrong.**
