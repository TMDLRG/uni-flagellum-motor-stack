=================================================
Base: 1fc6758 (audit/phase-a-findings tip), audited commit 9c3a644e

CLAIM
scripts/run-observed-experiments.mjs:35 performs fs.copyFileSync(datasetPath,
publicEventsPath), copying eol=crlf source bytes over an eol=lf mirror. This
corrupts a hash-pinned evidence artifact on every regeneration.

ACCEPTANCE CRITERION
Running the generators changes ZERO tracked files. Currently it changes exactly
one: public/wadhwa-2022-derived-events.json, 487890 -> 508103 bytes,
sha256 d119ca60... -> 32ec7ebf...

FAILING TEST — ALREADY EXISTS, NOT WRITTEN FOR THIS FIX
tests/walkthrough.test.mjs:58 and :63 hash the served mirror against its pins
and fail correctly after regeneration. tests/red/c3-raw-byte-identity.test.mjs
C3e encodes the same defect explicitly.

MINIMAL CORRECTION
Replace the raw byte copy at line 35 with a canonical-LF write, mirroring the
pattern already used correctly in-repo at scripts/run-science-gates.py:590
(write_text(..., newline="\n")). Line 34's protocol copy is NOT changed: both
sides are eol=lf, 7383 bytes, zero carriage returns, so it crosses no boundary.

WHY NOT THE OTHER CANDIDATE CORRECTION
Unifying the .gitattributes eol attribute would change the on-disk bytes of
experiments/data/wadhwa-2022-events.json from 508103 to 487890, changing its
sha256 from 32ec7ebf to d119ca60 and breaking the pin at
experiments/results/audit-manifest.json:18, which would cascade into runId and
every downstream artifact. That is not the smallest correction. It is deferred.
